# Предложение: Docker-инфраструктура

## Цель

Подготовить локальную Docker Compose-инфраструктуру для учебного проекта формы заявок: обратный прокси Nginx, PostgreSQL, pgAdmin, приватный Docker Registry и Watchtower. Будущий backend должен быть обозначен в Compose-комментарии без запуска контейнера.

## Область изменений

- Создать `docker-compose.yml` с сервисами Nginx, PostgreSQL, pgAdmin, Docker Registry и Watchtower.
- Создать конфигурацию Nginx для статического frontend и будущего backend-прокси.
- Настроить постоянное хранение данных PostgreSQL и Registry в Docker volumes.
- Настроить изолированные Docker-сети: публичную для Nginx и Registry, внутреннюю для PostgreSQL и pgAdmin.
- Сделать Registry доступным извне по IP-адресу сервера и порту.
- Включить базовую авторизацию Registry через файл `htpasswd`, совместимую с `docker login`.
- Добавить пример переменных окружения без реальных секретов.
- Описать запуск, создание учётных данных Registry и настройку Docker-клиента для HTTP Registry.

## Вне области изменений

- Реализация backend и frontend.
- Создание схемы базы данных и миграций.
- Настройка TLS для Registry.
- Автоматизация установки Docker Engine или Docker Compose на хосте.
- Публикация сервисов в интернет.

## Пользовательское поведение

- Nginx принимает HTTP-запросы на опубликованном порту и раздаёт frontend из каталога проекта.
- PostgreSQL не публикует порт хоста и доступен только контейнерам внутренней сети.
- pgAdmin доступен через Nginx, а не по собственному опубликованному порту.
- Registry принимает push и pull по `http://IP_СЕРВЕРА:REGISTRY_PORT` только после `docker login`.
- Watchtower запускается только с явно заданной меткой у обновляемых контейнеров и не обновляет инфраструктурные сервисы без такой метки.

## Риски

- HTTP Registry передаёт учётные данные без шифрования и пригоден только для изолированной учебной сети.
- Все Docker-клиенты, публикующие образы, должны быть настроены на доверие к HTTP Registry как к `insecure-registries`.
- Файл `htpasswd` содержит хеши паролей и не должен попадать в систему контроля версий.

## Проверка

- Проверить синтаксис Compose командой `docker compose config`.
- Запустить сервисы командой `docker compose up -d`.
- Проверить доступность Nginx, pgAdmin через Nginx и API Registry `/v2/`.
- Выполнить `docker login`, `docker tag`, `docker push` и `docker pull` для тестового образа.
